# Agent 选题：Minecraft 联机设施建设 Agent

> 说明：本帖文案由 AI 辅助撰写。

## 场景

我和朋友们时常一起联机玩 MC Java 版。Java 版的联机机制复杂：同一局域网可以直接开放世界，跨网络就需要公网 IP 或内网穿透；更麻烦的是账号，因为朋友们并非都有正版账号，想容纳离线玩家就必须自建服务器、把 `online-mode` 关掉；玩法上我们有时玩原版或插件服（Spigot/Paper），有时玩 mod 服（Fabric/Forge）并安装暮色森林这类 mod；再加上 Java 版本对应（如 1.21 需要 Java 21）、内存分配、EULA 协议确认、防火墙端口……类似的复杂分支还有很多。联机形态也不固定：偶尔在局域网里临时开个世界，更多时候需要一台能长期运行、存档连续的独立服务端，大版本更新后还要处理整服升级。这是一个真实、高频、且随版本更新不断变化的场景。

## 痛点

开服所需的知识散落在 Wiki、论坛帖和视频教程里，且随游戏与 mod 生态的演进快速过时。对普通玩家来说，开一个"能容纳离线朋友的 1.21 Fabric mod 服"动辄耗掉一个下午：要自己做十几步决策，要在配置文件和各种启动器之间来回试错，一旦报错只能把崩溃日志贴进搜索框碰运气。就算侥幸开起来，事情也没有完：电脑重启后地址变了、mod 与新版本不兼容、某个朋友突然连不上了……每一次故障都意味着重新搜索、重新试错。联机的快乐，被开服的门槛吃掉了。

## 通用 Agent 为什么解决不好

我已用 OpenCode 接入 GLM-5.2 在 Windows 11 上完成了基线实验：在我以小白语气提问、并持续提供专业级引导的前提下，通用 Agent 能够一步步把服务器搭起来，但过程非常坎坷，每隔几步就出现一次偏差，典型问题包括：版本号信息过时、下载渠道不合理、幻觉（例如认为 1.21.11 版本新于 26.2 版本）、漏掉混合认证 / 内存 / 穿透等分支、出错后定位不到根因。它没有固化的场景工作流，没有进度展示、配置沉淀和费用统计，每次都从零开始。**通用 Agent 需要一个懂行的人全程盯着才能完成这件事，而"懂行的人"恰恰是不一定存在的角色。**

## 打算做什么

我想为 Minecraft Java Edition 多人联机场景做一个"开服管家"式的专用 Agent：玩家用自然语言描述需求，它就在本机把服务器搭好、把隧道通好、把故障修好、把配置管好。用 Rust 从零实现，核心定制包括：

1. **开服决策树工作流**：把账号类型（正版 / 离线 / 混合）、服务端选型（原版 / Spigot / Paper / Fabric / Forge）、MC 与 Java 版本对应、内存分配、EULA 与防火墙等分支，固化为 Rust 编排的执行流程，LLM 只负责理解自然语言需求、在模糊处决策。玩家说"5 个人，2 个正版 3 个离线，玩暮色森林"，Agent 就推导出从认证策略到启动参数的完整方案——不会像通用 Agent 那样漏掉混合认证、内存这类玩家没主动提到的分支。

2. **版本兼容知识库 + 实时校验**：内置 MC × Java × 加载器 × mod 的版本对应知识，安装前实时调用 Mojang / PaperMC / Fabric / Modrinth 官方 API 核对版本是否存在、依赖是否满足，下载只走官方渠道并校验文件——从机制上杜绝实验中观察到的版本幻觉与失效下载渠道。

3. **内网穿透编排**："没有公网 IP"是好友联机最常见的拦路虎。Agent 根据玩家条件（有没有 VPS、能否付费、朋友们愿不愿意装软件）在 frp、playit.gg、Tailscale 等方案中自动选型，代为安装、生成配置、启动隧道、放行防火墙并验证端口可达，最后直接产出一份"朋友们怎么连"的说明；日后连不上时，沿"本机监听 → 防火墙 → 隧道状态"的链路自动排查。这件事通用 Agent 只能给出一段科普，因为它需要真实的安装、执行与连通性验证。

4. **MC 崩溃日志诊断（选）**：针对 Java 版本不匹配、端口占用、mod 不兼容等特征报错建立错误模式库，结合 LLM 定位根因并执行修复动作，而不是建议玩家"重新装一遍试试"。

在此之上完整实现课程 R1–R6 要求：模型可配置、长任务进度实时渲染且可打断、服务器配置档案可保存 / 加载复用、token 用量与费用统计及预算控制。

目标用户：不想研究运维的普通 MC 玩家。
预期效果：一句话开服，外网朋友直接连得进来，报错自己会修，下次开服一键复用。
